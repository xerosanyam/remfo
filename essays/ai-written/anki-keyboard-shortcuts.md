# Anki desktop keyboard shortcuts relevant to `remfo-nin`

Checked 2026-09-15 against Anki Desktop 26.09.2, the current official release at the time of research. Sources are the official Anki manual and the released source at commit `bb0dd6d1310afe290dea5e5a440400f851789936`. ([release](https://github.com/ankitects/anki/releases/tag/26.09.2), [source tag](https://github.com/ankitects/anki/tree/bb0dd6d1310afe290dea5e5a440400f851789936))

## Review screen

- Before the answer is revealed, `Space`, main-keyboard `Enter`/`Return`, and numpad `Enter` reveal it. The manual describes `Space` and `Enter`; the reviewer registers Space, `Key_Return`, and `Key_Enter` to one state-aware handler, which collects a typed answer when applicable and then reveals the answer. ([manual](https://docs.ankiweb.net/studying.html#keyboard-shortcuts), [shortcut registrations](https://github.com/ankitects/anki/blob/bb0dd6d1310afe290dea5e5a440400f851789936/qt/aqt/reviewer.py#L594-L641), [state handler](https://github.com/ankitects/anki/blob/bb0dd6d1310afe290dea5e5a440400f851789936/qt/aqt/reviewer.py#L657-L671), [typed-answer path](https://github.com/ankitects/anki/blob/bb0dd6d1310afe290dea5e5a440400f851789936/qt/aqt/reviewer.py#L800-L805))
- After the answer is revealed, `Space` or either Enter key rates the card `Good` by default. If an answer button has keyboard focus, Anki activates that button instead. This second action can be disabled by the “Spacebar also answers card” preference, whose implementation currently gates the shared Space/Enter handler. ([manual](https://docs.ankiweb.net/studying.html#keyboard-shortcuts), [state handler](https://github.com/ankitects/anki/blob/bb0dd6d1310afe290dea5e5a440400f851789936/qt/aqt/reviewer.py#L657-L671), [default ease and labels](https://github.com/ankitects/anki/blob/bb0dd6d1310afe290dea5e5a440400f851789936/qt/aqt/reviewer.py#L884-L905), [focused-button lookup](https://github.com/ankitects/anki/blob/bb0dd6d1310afe290dea5e5a440400f851789936/qt/aqt/data/web/js/reviewer-bottom.ts#L57-L63), [preference default](https://github.com/ankitects/anki/blob/bb0dd6d1310afe290dea5e5a440400f851789936/qt/aqt/profiles.py#L556-L560))
- Rating keys do nothing before reveal. Anki registers the rating shortcuts globally for the review state, but `_answerCard()` immediately returns unless the reviewer is in its `answer` state. ([registration](https://github.com/ankitects/anki/blob/bb0dd6d1310afe290dea5e5a440400f851789936/qt/aqt/reviewer.py#L594-L641), [state guard](https://github.com/ankitects/anki/blob/bb0dd6d1310afe290dea5e5a440400f851789936/qt/aqt/reviewer.py#L531-L537))
- After reveal, the defaults are `1` = Again, `2` = Hard, `3` = Good, and `4` = Easy. The keys are user-configurable in current Anki, but those four digits are the defaults. ([manual](https://docs.ankiweb.net/studying.html#answer-buttons), [labels](https://github.com/ankitects/anki/blob/bb0dd6d1310afe290dea5e5a440400f851789936/qt/aqt/reviewer.py#L884-L905), [default key map](https://github.com/ankitects/anki/blob/bb0dd6d1310afe290dea5e5a440400f851789936/qt/aqt/profiles.py#L128-L130))
- Both top-row digits and numpad digits with Num Lock producing `1` through `4` match. Anki installs `1` through `4` as Qt shortcuts and pins Qt 6.11.2; that Qt shortcut matcher explicitly retries keypad events after removing `KeypadModifier`. ([Anki key map](https://github.com/ankitects/anki/blob/bb0dd6d1310afe290dea5e5a440400f851789936/qt/aqt/profiles.py#L128-L130), [Anki Qt pin](https://github.com/ankitects/anki/blob/bb0dd6d1310afe290dea5e5a440400f851789936/qt/pyproject.toml#L35-L40), [Qt 6.11.2 matching logic](https://github.com/qt/qtbase/blob/v6.11.2/src/gui/kernel/qshortcutmap.cpp#L338-L342))
- Anki exposes shortcut hints as hover tooltips rather than adding numbers to the visible answer labels. The manual says hovering a button generally shows its shortcut; the answer-button renderer puts the configured key in each button's `title`. ([manual](https://docs.ankiweb.net/studying.html#keyboard-shortcuts), [button renderer](https://github.com/ankitects/anki/blob/bb0dd6d1310afe290dea5e5a440400f851789936/qt/aqt/reviewer.py#L912-L938))

## Add/record screen

- `Tab` moves forward through editor fields and `Shift+Tab` moves backward. This is native focus traversal rather than a separate Anki command: each editable field is in the tab order with `tabindex="0"`, and Anki's editor API explicitly treats pressing Tab as user-initiated field focus. ([editable field](https://github.com/ankitects/anki/blob/bb0dd6d1310afe290dea5e5a440400f851789936/ts/lib/editable/ContentEditable.svelte#L44-L59), [field-focus contract](https://github.com/ankitects/anki/blob/bb0dd6d1310afe290dea5e5a440400f851789936/ts/routes/editor/EditingArea.svelte#L10-L23))
- `Ctrl+Enter` adds the note on Windows and Linux; `Command+Enter` adds it on macOS. Enter alone is not the Add shortcut. ([manual](https://docs.ankiweb.net/editing.html#adding-cards-and-notes), [Add button source](https://github.com/ankitects/anki/blob/bb0dd6d1310afe290dea5e5a440400f851789936/ts/routes/editor/AddButton.svelte#L5-L17))
- The Add button shows the platform-formatted shortcut in a tooltip, matching the requested hover-only presentation. ([Add button source](https://github.com/ankitects/anki/blob/bb0dd6d1310afe290dea5e5a440400f851789936/ts/routes/editor/AddButton.svelte#L5-L17))

## Minimal compatibility target for Remfo

1. Record: keep native `Tab`/`Shift+Tab` field traversal and add `Ctrl+Enter` plus `Command+Enter` submission.
2. Revise, question visible: `Space` and both Enter variants reveal the answer; `1` through `4` do nothing.
3. Revise, answer visible: `1` through `4` choose the four ratings; `Space` or Enter chooses Good.
4. Accept both top-row and numpad digits, and put shortcut text in hover tooltips only.
